Blueprint approval: temperature-converter
Branch: integration/temperature-converter
Summary: Build a dependency-free Node.js CLI invoked as node bin/temperature.js <temperature> <unit>. Separate temperature arithmetic, argument validation, and command execution into three modules. Define exact parsing, formatting, help, diagnostics, and exit-status behavior. Deliver source, local instructions, and built-in Node tests; use no network, accounts, or database.
Modules:
- M1 Temperature arithmetic: Own src/temperature.js: canonical temperature types, destination selection, and finite Celsius/Fahrenheit conversion. (R3, R4)
  Boundary: picked Pure conversion over Temperature objects
- M2 Command argument grammar: Own src/arguments.js: positional syntax, unit aliases, numeric validation, help recognition, and generated usage text. (R1, R2)
  Boundary: picked Validated command parser over Caller-owned parsing pipeline
- M3 CLI execution and presentation: Own src/cli.js and bin/temperature.js: execute one command, format its output, and translate the result into process streams and exit status. Own package.json, README.md, and test/cli.test.js. (R1, R5)
  Boundary: picked Buffered command result with process adapter over Executor with injected process services
ADRs:
- ADR1 Deliver a local Node.js CLI: Dependency-free local Node.js CLI
- ADR2 Separate arithmetic, argument knowledge, and process presentation: Three modules with pure conversion, validated parsing, and buffered command execution
- ADR3 Use strict positional parsing and deterministic diagnostics: Two positional arguments with full-token numeric validation
- ADR4 Use native floating-point arithmetic and deterministic decimal rendering: Native Number conversion, finite-result checks, and explicit decimal rendering
- ADR5 Deliver source and verify with Node's built-in test tools: Private ES-module source project with node --test and direct node execution
Departures from the default stack:
- One hosting-model departure: a local Node.js CLI replaces the default scaffold-app web application and its frontend/backend scaffold. instead of Vue 3, Vite, Tailwind CSS, shadcn-vue, Pinia, Express 5, Passport, Knex, and PostgreSQL web scaffold.
Knowledge:
- K1 Canonical Celsius/Fahrenheit unit constants and the Temperature value/unit contract.: owner src/temperature.js, built in S2
- K2 The untrusted command-argument contract: arity, sole-help recognition, decimal grammar, finite-number validation, unit aliases, and corresponding usage text.: owner src/arguments.js, built in S3
Unverified premises:
- The completed application will pass its declared Node >=22 baseline and execute consistently on Windows, macOS, and Linux. (No application exists yet. Only Linux runtime probes on Node v24.21.0 were executed; the oldest supported runtime and other operating systems require acceptance verification.)

- S2 Implement finite temperature arithmetic: Implement M1 in src/temperature.js and test/temperature.test.js, changing these two files plus knowledge-map bookkeeping. Build K1 at src/temperature.js for M1, M2, and M3: export Object.freeze({ celsius: 'C', fahrenheit: 'F' }) as UNITS and export JSDoc Unit and Temperature contracts, deriving Unit from UNITS and defining Temperature as { value: number, unit: Unit }. Export pure convert(temperature), returning { ok: true, temperature } or { ok: false, code: 'NON_FINITE_RESULT' }. For validated canonical inputs, select the opposite scale and calculate Celsius input as value * (9 / 5) + 32 and Fahrenheit input as (value - 32) * (5 / 9). Check Number.isFinite on the computed result. Honor A5 and ADR4: native binary64 arithmetic, no physical limits, rounding, parsing, formatting, process effects, or exceptions for expected overflow. Assert independently stated expected conversions rather than relying solely on round trips. (requirements: R3, R4; depends on: S1; criteria: 3)
- S3 Implement the complete command-argument contract: Implement M2 in src/arguments.js and test/arguments.test.js, changing these two files plus knowledge-map bookkeeping. Import K1 and build K2 at src/arguments.js. Export USAGE and parseArgs(argv), returning { kind: 'help' }, { kind: 'convert', temperature }, or { kind: 'error', message }. Recognize help only for a sole trimmed, case-sensitive -h or --help. Otherwise require exactly two positional arguments, trim both, validate number before unit, and accept the complete decimal grammar ^[+-]?(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)(?:[eE][+-]?[0-9]+)?$ before Number conversion and Number.isFinite checking. Accept native underflow to zero and impose no physical bounds. Own one ordered alias table for C, Celsius, F, Fahrenheit, referencing imported UNITS; match case-insensitively and generate usage alternatives and the diagnostic unit list from that table. USAGE must equal 'Usage: node bin/temperature.js <temperature> <C|Celsius|F|Fahrenheit>'. Use exact errors 'missing temperature or unit.' for fewer than two arguments, 'expected exactly two arguments.' for more than two, 'temperature must be a finite decimal number.' for invalid numbers, and 'unit must be C, Celsius, F, or Fahrenheit.' for unsupported units. Honor Q2 and A4–A8: no stdin, prompts, general option parser, or -- separator. (requirements: R1, R2; depends on: S2; criteria: 4)

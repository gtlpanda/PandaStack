# SA-01: snapshot permission-bit prerequisite (draft)

Scope: source-only audit init checks the actual resulting filesystem mode bits after export/seal and before publishing run metadata or a dispatchable stage. This is NOT arbitrary same-user containment, ACL enforcement, actual denied-write proof, read-only mounts, or target execution authorization. Source-only reader enforcement belongs to the separate native transport feature. Root may bypass DAC; no root skip implies protection. Old tests remain unchanged.

New owning module `graphs/security-audit/skills/security-audit/snapshot-protection.mjs` exports synchronous `inspectSnapshotProtection(tree) -> {ok,problems}`. `tree` is an absolute filesystem path. No callbacks/public injected stat authority. It performs lstat/readdir only, never chmod/write/open-for-write or follows symlinks. Inspect root and all regular descendant directories/files. Writable mode mask0222 is a problem regardless of actual user. Root must be a real directory. Symlinks and other nonregular entries are refused without traversal. Missing/unreadable/invalid root is failure, never success or empty snapshot. Empty nonwritable directory is valid for this prerequisite.

Exactly `problems:[{path,code}]`, path relative POSIX path, root `.`. Codes `WRITABLE`, `SYMLINK`, `NOT_REGULAR`, `NOT_DIRECTORY`, `IO_ERROR`, `INVALID_ROOT`. Deterministic codepoint sorting by path then code; no absolute path, exception message or source contents in diagnostics. Non-directory root gets NOT_DIRECTORY (symlink root gets SYMLINK); reject relative/nonstring input with INVALID_ROOT. I/O failures get IO_ERROR, and retained observed problems are not discarded. ok iff problems empty. One WRITABLE row per writable entry. Directory write bits do not stop safe enumeration. Symlink entry gets SYMLINK only, never tests target mode/contents. Data returned detached; inputs not mutated.

Init directly imports this function. When budget permits export, call it on exact exported tree after exportTree returns and before writing run-metadata/stage/events or discovering prior agents' work. If !ok, refuse with safe fixed summary and no success notes; existing init-owned cleanup policy applies. No new metadata schema is required. A budget refusal still creates its existing incomplete record without snapshot inspection, and never launches agents. The draft static wiring case deliberately requires a direct named call/guard in init to make the order reviewable; if implementation uses an equivalent helper, report the fixture mismatch for independent revision instead of weakening behavior silently.

Future ordinary filesystem tests create only inert owned directories/files, set ordinary mode bits, inspect actual lstat results, then clean those exact directories. Linux temp and explicit Windows-mounted temp parent are independent fixtures. The mounted case derives expected pass/fail from actual mode bits, not chmod's return value or mount name: ignored chmod yields !ok. It does not require Windows-mounted storage to be unsupported if its modes really comply. Missing mount/temp prerequisite is an explicit test failure/incomplete gate, never skip-as-positive. No target repo writes, race, signal, owner/capture or lifecycle workload.

Acceptance file imports missing new module before filesystem setup, so authorized initial run should fail only module-not-found. Preparation does not execute tests. Existing tests use workflow-harness; new independent draft uses node:test to isolate future acceptance from that harness's global summary. Install location proposed acceptance/security-audit/sa-01-snapshot.test.mjs with ROOT ../../ or explicit PANDASTACK_CANDIDATE_ROOT. Static init case complements actual filesystem inspector checks; no runtime init failure injection is claimed.

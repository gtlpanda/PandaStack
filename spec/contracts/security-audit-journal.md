# SA-02a: ordinary durable leaf journal (proposed freeze)

External draft only; tests not executed. New module graphs/security-audit/skills/security-audit/dispatch-journal.mjs. This first slice does not implement native scheduling, providers, report generations, budget adjustment, retries or source execution. No blocked capture/race reproduction is authorized.

Existing core/skills/run-records/store.mjs is an append/immutable run-event store with schema-specific validators and internal descriptor-safe storage; it exports no reusable lease or generic job transition transaction. Reusing it as a mutable job ledger would misrepresent its records. Keep this slice audit-local; factor a generic native-runtime owner only when a second real consumer exists. Reuse accepted storage discipline, not incompatible run schemas or a new speculative framework.

Exports:
* openAuditJournal({runDir,invocationLimit}) -> handle, synchronous. runDir must be a real existing audit run validated by owning loadRun AND the explicit identity checks below (loadRun alone does not validate identity); invocationLimit safe integer >=0, immutable on reopen. Legacy metadata budget remains untouched. Existing complete/incomplete run rejects new creation/execution with TERMINAL_RUN. Unknown options rejected.
* readAuditJournal(runDir) -> detached {version:1,runId,sourceRef,invocationLimit,settledCalls,heldCalls,available,rows}. Read-only, no owner acquisition/no mutation; absent NOT_FOUND. rows stable creation order, exact row {id,input,state,result}; input is detached finite JSON record; result null until terminal known. state prepared/dispatched/returned/failed/uncertain. result for returned is arbitrary finite JSON; for failed exactly {code} safe uppercase identifier. No prompts/errors in error messages.
* handle.prepare({id,input}) -> {created,row}. id safe /^[A-Za-z0-9][A-Za-z0-9_-]{0,79}$/; input normal or null-prototype finite JSON data record, no hooks/accessors/custom prototypes. Full canonical equality binds input, not merely a caller digest. One prepared row holds one invocation. Exact replay unchanged; different input CONFLICT; insufficient capacity BUDGET_EXHAUSTED with no row. On reopening, prepared stays safely runnable; dispatched becomes uncertain durably before returning handle (no automatic resend).
* await handle.execute(id,invoke) -> {replayed,outcome,result}. invoke is a trusted programmatic callback supplied by owning host, not config/CLI/model data. It is invoked with detached input only after dispatched state is durably committed. Callback returns exactly {outcome:'returned',result:<finiteJSON>} or {outcome:'failed',result:{code:<safeCode>}}. Such explicit failure is a trusted transport adapter's known terminal result; untrusted model content must remain returned data for later semantic validation. Returned-invalid agent JSON can still be a returned string. Wrapper stores outcome durably BEFORE its promise resolves. Known terminal row replay returns stored result without invoking callback. Prepared transitions once; dispatched/uncertain refuses DISPATCH_UNCERTAIN. Callback throw, rejection or invalid transport envelope => durably uncertain, heldCalls retained, throw DISPATCH_UNCERTAIN; no raw exception echo. If terminal persistence fails, fail IO_ERROR, retain charged state, never return successful result. No automatically repeated callback.
* handle.cancelPrepared(id) -> {changed}. Deletes only prepared row, freeing its hold; missing returns changed:false; any dispatched/terminal/uncertain row CONFLICT, unchanged. This is cancellation before invocation, not proof that a running provider stopped.
* handle.close() -> void, idempotent. Refuses BUSY while any execute callback unsettled, leaving ownership held. Otherwise flush/releases own lease. All subsequent mutating handle methods CLOSED; readAuditJournal remains available. Unknown rows remain held across normal close/reopen.

Owner lifecycle is concrete: open acquires an exclusive host-created private lock file using exclusive creation, retained file descriptor and random owner nonce; no caller owner/PID/proof argument. Keep this lock through handle lifetime. Refuse OWNER_BUSY whenever lock exists, including after abnormal process death; NO timestamp/PID-based stale takeover or lock-deletion CLI in this slice. Host restart after clean close works. Crash lock recovery is deliberately unavailable pending separately reviewed local owner reconciliation; never advertise automatic crash recovery merely because row replay works. Safe close removes only the own matching lock identity. Ordinary test cases exercise same-process duplicate opens only, no process race/kill. Failed initialization must release only its newly acquired lease. Sidecar data/lease stored under dedicated native-dispatch child, private0700 directories/0600 regular files; follow existing accepted no-symlink policy and retain operational IO_ERROR versus malformed CORRUPT. Do not change permissions or contents of pre-existing unsafe entries.

Storage transactions atomically persist validated per-row changes and sync before acknowledgement (Node24 SQLite accepted with the accepted private-storage policy and durable settings). Do not rewrite all prior prompts/results on each completion; use transactional per-row persistence or a bounded index with immutable body records. No transaction held uncommitted across callback. Prepared+dispatched+uncertain each count heldCalls1; returned+failed count settledCalls1. available=limit-settled-held, never negative. Identity, ordering, counters and JSON boundedness validated on every read; malformed state CORRUPT, not guessed repair. Per input and per result limit is1MiB canonical serialized UTF8 JSON; at most10000 rows and1GiB total serialized journal content per run. There is NO1MiB whole-journal limit. Total serialized content counts canonical UTF8 row and header data, including every retained input/result once; physical SQLite page/WAL overhead is not this logical content limit. Admission reserves the maximum small control-state expansion for every pending row (including dispatched/uncertain markers and derived counters), so a fitting prepared row can always record dispatch/uncertainty without needing capacity growth. A result within its per-result limit but exceeding remaining total content capacity is not acknowledged: persist the already-reserved small uncertain state with null result and reject DISPATCH_UNCERTAIN. Prepare exceeding per-input, row-count or total-content capacity rejects INPUT_TOO_LARGE without mutation. No automatic cap increase. Counters derive from validated rows rather than independent mutable storage authority. Separate bounded header/index metadata from body storage; readAuditJournal may assemble all rows but must validate each bound without integer overflow. Actual persistence failure remains IO_ERROR, never a successful callback acknowledgment. No dollar field. This slice does not project agents_spent: original metadata/ledger/state bytes remain unchanged. Later host integration owns exactly-once accounting projection and two-attempt logical policy; this primitive does not authorize retries under new IDs.

Acceptance uses node:test with actual audit init fixture and existing workflow-harness load/run for one ordinary synthetic callback interaction. Missing module import precedes any fixtures. No runtime executed during preparation. Assertions prove disk-visible intent/result ordering, not physical inference execution guarantees. Existing schema/validator files and baseline tests unchanged.

## Validation/error closure for this slice

Complete public error codes: INVALID_JOURNAL_INPUT (invalid options/keys/IDs/data/limit), INPUT_TOO_LARGE (input or admission capacity bound), CONFLICT (different replay payload, immutable limit/source identity mismatch, forbidden cancel), BUDGET_EXHAUSTED, OWNER_BUSY, BUSY, CLOSED, DISPATCH_UNCERTAIN, TERMINAL_RUN, NOT_FOUND, CORRUPT, IO_ERROR. Unknown ID execute is NOT_FOUND. Unknown handle options or prepare fields reject; check descriptors before reading values so getters never execute. All rejected pre-dispatch validations leave durable state unchanged and release any newly acquired lock. Safe errors must not contain input, callback exception or source content.

execute always returns a Promise; a closed handle rejects it with CLOSED before any callback or row mutation. prepare/cancelPrepared on a closed handle synchronously throw CLOSED. close remains idempotent. Runtime source identity and terminal status are revalidated on open and before every prepare/execute grant, not trusted solely from cached metadata. Terminal guard takes precedence over new dispatch; existing readAuditJournal remains a read-only inspection path. Symlinked native-dispatch is CORRUPT with no chmod/adoption/writes through the link. Input/result serialized limit is UTF8 byte length of JSON, not character length; finite plain data descriptor validation precedes serialization.

The added ordinary source-metadata fixture restores exact original bytes in finally before other cleanup. Static symlink fixture is created once and never concurrently replaced; it proves refusal only, not filesystem-race resistance. All draft cases remain unexecuted at preparation time.

## Exact persisted run identity validation

Before creating native-dispatch or taking its lease, read owning metadata as inert JSON and validate: version===1; run_id,repo,target are nonempty strings, matching the existing audit-run checkRun identity rules; source_ref is a data record with commit accepted by exported isCommitId (lowercase40 or64 hex), tree likewise40 or64 lowercase hex of the same length, and dirty boolean. tree is an additional journal binding requirement because actual init emits it; its absence must not be invented from commit. If uncommitted is present, it is a record with tracked/untracked nonnegative safe integers. Identity binds version,run_id,repo,target and the full source_ref canonical value. No run_id-as-path interpolation. Malformed identity is CORRUPT and creates no journal/lease; well-formed different bound identity is CONFLICT. Revalidate on each open and before execution/admission. Tests mutate only owned metadata and restore exact bytes in finally. This does not tighten the original metadata validator or rewrite historic runs; an incompatible historical run simply cannot acquire the new journal authority.

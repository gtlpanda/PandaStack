# Critic partition pure planner — engineering proposal, not frozen

This new narrow proposal replaces only SA-D4 API ambiguity. It does not activate the historical native-journal proposal. SA-02a owns journal prepare/execute and NR02 owns runtime dispatch. No fixture execution authorized by this draft.

Proposed owner: graphs/security-audit/skills/security-audit/critic-partitions.mjs.
Exports planCriticBatch({identity,shared,items}, {measureScript}), planCriticReconciliation({manifest,results},{measureScript}), acceptCriticReconciliation({manifest,results,plan,result}). All synchronous pure functions, no filesystem/provider/callback dispatch. measureScript is a trusted host serialization function returning actual generated UTF8 script byte count, not caller JSON authority. Production must use exact current run-script INJECTED_INPUT serialization; tests independently use that literal replacement without executing code. Cap is fixed 500000, no supplied override. Registry captures actual template; no arbitrary source evaluated.

identity exact {runId,sourceRef:{commit,tree},kind,wave,profile}; kind post-wave/final-clean, wave positive safe integer, profile quick/standard/deep; quick final-clean invalid. Full hashes 40 or64 lowercasehex with matching lengths. Shared exact full host selected {architecture_md,parts,execution,tree}; these are data, never instructions overriding host policy. items nonempty array of exact {itemId,kind,owners,value}, kind unit/candidate/prior. itemId unique nonempty bounded128; owners unique existing unit item IDs (unit owns itself); every candidate/prior associated with every applicable unit by trusted adapter, unassociated global records owners all units. Values full finite JSON records with no getters/proxies/custom prototypes/cycles, detached. Input array order is preserved canonical host order (ledger order then candidates then prior), not sorted by model output. Upstream unit/candidate validation remains host prerequisite; this planner only validates envelope/references, never claims semantic validity of arbitrary ledger records.

Manifest {version:1,batchId,inputDigest,identity,shared,items,partitions}; item adds digest SHA256 canonical recursive sorted JSON value. Input digest includes exact identity/shared/items; batchId='critic-'+digest. Each unit bundle includes full unit and all linked candidate/prior values; duplicates permitted across owners, never omitted. Partition greedily packs consecutive unit bundles while measured script <=500000; last valid partition emitted before next, deterministic partId='part-'+1basedindex. Partition exact {partId,itemIds,inputDigest,input,scriptBytes}; input contains {stage:'critic',part:'critic',identity,shared,index,items}; index lossless identity/kind/owners/digest list for ALL items, item details full for this partition. inputDigest hashes exact input. No clipping of prose/list/paths/attempts/prior/candidate fields. If shared/index or a single bundle exceeds cap throw STAGE_INPUT_TOO_LARGE, unchanged input; no automatic dropping or hierarchy. Limits/errors generic; concrete 122-unit fixture below must partition successfully, not return incomplete. Hashes are consistency bindings, not provenance/authentication.

results unordered array of exact {batchId,partId,inputDigest,critic,summary}; summary finite record {text,itemIds}, text <=4096UTF8, itemIds exactly that part's item IDs. critic uses existing criticResultProblems; retain upstream open missing_units records. Also validate IDs belong to full manifest: reassign_ids refer unit coverage_id values and resolved_prior_leads refer prior value.fingerprint. Duplicate result ID/conflicting/stale/extra malformed =>INVALID_PARTITION_RESULT. Missing required parts yields reconciliation {complete:false,missingPartIds,plan:null}; no global dispatch permission. Complete returns {complete:true,missingPartIds:[],plan:{batchId,inputDigest,input,scriptBytes}} where input includes full identity/status index, exact part digests, all summaries and all partition critic proposals plus manifest item references. Raw values remain unchanged in manifest. References are not proof of model inspection. Global input <=500000 or explicit STAGE_INPUT_TOO_LARGE; required fixture fits. Returned plan hash binds all complete part results, so changed proposals/summary cannot reuse it.

Global result exact {batchId,inputDigest,critic}; missing result yields {complete:false,critic:null}; stale/malformed throws INVALID_PARTITION_RESULT. accept recomputes plan consistency from manifest/results (must not accept self-asserted hash) and requires all partitions. Final {complete:true,critic} unions missing_units by canonical equality and reassign IDs in manifest order; prior resolution only if every owning partition AND global resolves it. stop only if every part AND global says stop, and no retained missing_units/reassign work. Global cannot erase part proposals. Existing applyCriticProblems, minter and nextStep still decide legal application; pure completion is not scheduler advancement or verified finding.

Integration feature required separately: persist manifest before SA02a reservations, bind each NR02 leaf to exact part/global digest, persist each terminal envelope before replay, global only after all valid parts, apply existing critic aggregate once only after accepted global. Resume uses unchanged manifest and completed rows; no new logical IDs on retry. Enforce actual full input adapter, source-only manifest reader and global semantic prompt; fake results prove barrier only, not actual cross-subsystem review. No competing scheduler/ledger or spent double count.

## Exact executable projection and narrow graph context proposal

Metadata exact {itemId,kind,owners,digest}; values appear losslessly once in top-level ledger/candidates/prior.records. Their order follows manifest. Global input has identical required top-level fields, ledger/candidates empty and prior.records empty, with critic_context mode:'reconciliation', batchId, index, and partitions in manifest order containing {partId,inputDigest,summary,critic,itemIds}. Global uses that lossless identity/status index (unit entries additionally carry coverage_id/status; candidate/prior entries fingerprint where defined). Full raw evidence remains manifest-owned retrievable data, not copied into global input.

Narrow owning workflow change required: optional critic_context, absent retains legacy behavior. Validate version/mode/shape and nonempty IDs before dispatch. Partition prompt states it owns only its listed full-detail subset, prints context in untrusted-critic-context fence, and removes the legacy sentence claiming prose was omitted/clipped for this mode. It must not call subset the entire ledger. Global mode prompt explicitly says 'global semantic reconciliation', mandates cross-subsystem gaps, conflicting conclusions and shared assumptions, includes all context proposals and summaries in that fence, and explains full evidence references require trusted reader. It must not claim empty top-level ledger is full coverage or summaries are complete evidence. All modes retain frame(), source-only execution and upstream criticSection/profile verbatim; output remains exact existing CRITIC_SCHEMA/criticProblem. Context supplies data only, never an executable path, tool grant or workflow override. Model cannot authorize reader or mark host receipts complete. Host adapter supplies manifest-scoped reader separately; fake graph tests establish prompt and barrier wiring only, not model inspection or runtime source-only enforcement.

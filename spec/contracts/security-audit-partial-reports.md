# SA-02b proposed partial-report generations

Concrete external SA-02b contract proposal; not frozen or implemented. Depends on accepted SA-02a journal and unchanged existing audit renderers/semantic validators. No new audit/provider execution, source changes, subprocess/race/capture probes or blocked reproduction. Actual native host callback integration is a later acceptance dependency; do not invent per-agent callbacks in the opaque Claude Workflow transport.

## Existing ownership and precise reuse

skills/security-audit/audit-report.mjs owns reportContext(:56), pure buildReports(:283), and final writeReport(:323). writeReport requires next=report, may finishRun/markIncomplete and advances stage; it MUST NOT be reused as a progress writer. reportContext can represent absent ledger/findings, but it also invokes candidate/decision linkage and needs validator rejection information before trusting files. audit-md.mjs owns inline/cell/fence/code/where escaping. Reuse those escaping functions and shared coverage/lead presentation helpers inside audit-report.mjs; do not introduce a second independent verdict renderer or alter final report behavior/golden files to accommodate partial output.

Add three exports to audit-report.mjs:

* `partialReportContext(runDir) -> context`: read-only coherent snapshot from current audit identity, stage, SA-02a readAuditJournal and existing source artifacts. No callback/provider/metadata mutation. Validates identity exactly as journal, validates present ledger/findings with existing vendored validators and present candidates/decisions through owning parsers/semantic checks. Invalid artifact is reported as rejected with a safe diagnostic and no counts/content from that artifact. Missing artifact is recorded absent; missing findings does NOT imply zero leads, successful verification or clean coverage.
* `buildPartialReport(context) -> string`: pure deterministic Markdown using existing audit-md helpers. Output is PROGRESS-REPORT, visibly PARTIAL/NOT FINAL, never a replacement REPORT.md. Includes exact source commit/tree, run ID, snapshot generation key, stage/profile, actual run status separately from report completeness, journal counts, pending work, known leads, coverage and explicit blockers/limitations. Does not assign new verdicts/severity or claim agent output is verified.
* `publishPartialReport(runDir) -> {status,generationKey,currentPath,reason}`: synchronous host-owned publisher using those two exports, no provider or scheduler calls. status published/replayed/failed/stale; reason null or safe code. No arbitrary destination option. It writes only the dedicated partial-reports namespace. In ordinary I/O failure return failed/IO_ERROR with currentPath:null; it must not throw past a native completed-leaf callback and cause a provider retry. Invalid authority returns failed with specific safe code. Rendering/programming failures safe RENDER_ERROR; never change journal state to failed because report failed.

`readPartialReport(runDir) -> {status:'current'|'stale'|'missing'|'invalid',generationKey,expectedGenerationKey,path}` is an additional read-only status helper, necessary to ensure consumers cannot silently label an old file current. No auto regeneration from this read. Path null for missing/invalid; stale path may identify historical artifact but status must remain stale. Use same context binding calculation as publisher, not a second freshness policy. If current sources cannot be validated well enough to compute expected key, return invalid with expectedGenerationKey:null, never current.

## Snapshot and generation binding

Context schema version1: `{identity,stage,profile,runStatus,incompleteReason,binding,journal,coverage,leads,blockers}`. identity includes runId,repo,target and full sourceRef. stage is exact current stage-state (not inferred from timestamps). binding contains rendererVersion (explicit constant), journalDigest, artifact digests/presence states and identityDigest; generationKey is SHA256 canonical finiteJSON of the binding. Artifact list fixed: run-metadata.json,stage-state.json,coverage-ledger.json,candidates.json,decisions.json,critic.json,findings.json. Hash raw bytes when present, an explicit absent token when absent; rejected artifact still bound by its hash and rejection state. Hash the detached validated journal snapshot canonically (or a journal-owned equivalent digest once accepted) when available; when unavailable, bind the safe error classification plus exact input artifact digests and explicitly label the generation incomplete; no invented mutable journal revision field. Same snapshot+renderer version yields same key; changed leaf state/input/result or source artifact yields a different key. Generation is content-addressed, not wall-clock sequence. No current-source pin is implied by a string supplied by a model.

Context builder reads under the single owning native host's serialized file publication boundary. The callback may finish while other provider promises remain pending, but host-side journal/result/report publication is serialized; no promise that independent unsynchronized external writers are supported. Before marking current, recheck all input digests. A changed binding returns stale and does not publish a current pointer; caller may retry rendering from a fresh snapshot without rerunning agents. Do not hold a filesystem transaction across provider callbacks.

## Readable content without false findings

Journal counts are exact prepared/dispatched/returned/failed/uncertain, settledCalls/heldCalls/available. Header explicitly says returned is transport completion, not semantic acceptance; failed or uncertain is not a rejected security finding. Count returned rows awaiting semantic application conservatively unless owning stage artifact/receipt proves a link; do not invent a link from text/IDs. PendingAgents=prepared+dispatched+uncertain with each category distinguished; future unplanned work is unknown, not zero. Unknown provider cost remains unknown; invocation budget is labeled calls.

Coverage is full status counts only from a valid ledger, with reviewed/deferred/blocked/planned/in_progress categories and exact unresolved reasons. Missing/invalid ledger gives coverage unknown and a blocker. Existing list truncation may be used only if an explicit count and exact source artifact reference identifies omitted entries. Never truncate away pending lead identities. Known provisional leads come from valid existing candidates and decisions and valid needs_validation records; union by owning fingerprint semantics, retain rejected dispositions distinctly, and do not promote raw journal strings/objects into candidates. Raw returned payload before owning semantic apply appears only as returned awaiting semantic review (dispatch ID and safe role if actually bound), not as a finding. Titles/paths/blockers use existing escaping, never executable links or model-directed reads. Explicit source-only disclaimer and absence of final verification remain visible.

No final artifact exists is normal: render at least identity, phase, journal/pending counts, unknown coverage, pending semantic results and blocker details after the first leaf settles while others are active. A valid candidate already published by owning merge/validator appears as an unverified lead. Full raw agent output stays in the journal; the report never leaks entire prompts or errors for convenience.

## Publication and failure recovery

Private fixed runDir/partial-reports0700; regular0600 files, same accepted static path/no-symlink policy as journal. Write one immutable `<generationKey>.md` and manifest `{version:1,generationKey,binding,markdownSha256,bytes}` as a matched generation, then atomically replace `current.json` LAST. Reader verifies pointer/manifest/file hashes and source freshness. Existing generation exact replay returns replayed; conflicting bytes for same key is CORRUPT, no overwrite. History is explicitly historical. Staging artifacts never count as current. A malformed/unsafe existing destination is refused without chmod/adoption; output file conflict is an ordinary deterministic I/O test, not a race probe.

A prior current.json surviving failed publication is not itself a false freshness claim: readPartialReport recomputes bindings and returns stale. CLI/native status must print that result, never print cached previous prose as latest. A direct reader of Markdown sees its exact snapshot key and a permanent statement that freshness requires current-source verification. No mutable 'live' label in immutable Markdown.

A completed native callback sequence is: durable terminal leaf receipt -> attempt partial publication -> return leaf result to trusted workflow regardless of observational report failure. Report status is separate: failure or stale publication sets native control report_stale, blocks admission of NEW dispatches, and drains already-inflight callbacks to durable known/uncertain receipts before pausing. This is a required readable-checkpoint guarantee, not an ignorable onEvent sink failure. Never reclassify the stored successful result as model failure or authorize its retry. On resume, reconcile durable terminal result without provider launch, call publishPartialReport to repair missing/stale output, and only after verified current generation clears report_stale continue existing scheduler. No journal receipt is deleted/reclassified to recover reporting. No markComplete/markIncomplete/advanceState/finishRun/event rewriting by these exports. The original REPORT.md/FINDINGS-DETAIL.md/NEEDS-VALIDATION.md remain exclusively owned by final writeReport and unchanged.

## Frozen-interface proposal: observable context fields

Exports remain partialReportContext, buildPartialReport, publishPartialReport and readPartialReport in audit-report.mjs. No new standalone owner. context.version=1; context.generationKey is lowercase64hex. context.identity={runId,repo,target,sourceRef}; context.stage is exact stage-state. context.journal={status:'available'|'unavailable',states:null|{prepared,dispatched,returned,failed,uncertain},settledCalls:null|integer,heldCalls:null|integer,available:null|integer,pendingAgents:null|integer}; context.coverage={status:'valid'|'missing'|'rejected',counts:null|all-eight-status-counts}; context.leads is sorted rows {fingerprint,disposition:'pending'|'needs_validation'|'rejected',blockers:[string],units:[string]}. No confirmed disposition is introduced by partial renderer. A previously validated confirmed record, if legacy fixture supplies one, is labeled historical-final-record with source reference outside leads, never a new partial finding. context.blockers is array of {code,message,artifact:null|string}; safe fixed codes include LEDGER_MISSING, LEDGER_REJECTED, FINDINGS_MISSING, FINDINGS_REJECTED, ARTIFACT_REJECTED, DISPATCH_UNCERTAIN, FINAL_VERIFICATION_PENDING. Missing candidates or decisions is permitted pre-merge, malformed present data is a rejection blocker. Unknown counts remain null rather than0; states from journal are known only after a successful owning read.

For pending candidate source, use existing pool fingerprint/record.title/unresolved blockers only after owning validation, and never infer semantic results from journal payload. Disposition pending until owning decisions establish needs_validation/rejected. Preserve source-only needs_validation. All valid pending fingerprint identities appear in Markdown; final artifacts absent is not 'no leads'. Existing artifact raw-byte bindings are exact, but context is detached and may be frozen.

Publication result exact fields status/generationKey/currentPath/reason. success reason null, currentPath points the immutable Markdown under partial-reports; failed reason safe code and currentPath null. For malformed generation/file pointer use CORRUPT; directory/file operational conflict IO_ERROR (no adoption). Reader exact fields status/generationKey/expectedGenerationKey/path; no success error property. Pointer current.json exact {version:1,generationKey,manifest:<relative fixed basename>}; manifest filename <key>.json, Markdown <key>.md. Manifest exact {version:1,generationKey,binding,markdownSha256,bytes}. File references must be regular nonsymlink confined basenames. Stage input changed since snapshot => stale result. Whole progress bodies bounded to16MiB; excess returns failed/REPORT_TOO_LARGE without dropping pending leads. Metadata pointer is bounded64KiB. No model-selected paths.

This helper slice exposes stale/current status but cannot prove future native dispatch obeys it. Required host integration dependency: after every terminal callback, publish; failed/stale -> native report_stale control, deny new dispatch, drain existing callbacks, pause; resume render only before reopening dispatch. Completed receipt stays terminal/successful and provider callback is not rerun. SA-02b helper tests do not claim that gate is wired; the native host acceptance must assert the actual gate before overall security completion. No rendering failure is treated as an optional ignored event sink.

## Authority-unavailable and bounded input closure (supersedes optimistic reads above)

Current journal implementation is not yet present at preparation review. Frozen SA-02a may call loadRun, which parses ledger/findings as well as identity. A malformed ledger may therefore prevent readAuditJournal. Report code MUST use readAuditJournal and never bypass it with raw SQLite/body reads, alter artifacts temporarily, or guess counts. Catch an owning read failure as journal.status unavailable with states/settledCalls/heldCalls/available/pendingAgents all null; add JOURNAL_UNAVAILABLE blocker with safe code only. It may still render independently validated identity and artifact-rejection details. This incomplete-evidence generation can be published for visibility, but readPartialReport.status is invalid (expectedGenerationKey:null) while journal authority is unavailable; it never clears report_stale. The immutable generation header explicitly says journal authority unavailable. Before freezing, inspect actual accepted journal to confirm this path; no claim that a malformed ledger leaves journal readable.

partialReportContext validates metadata and stage independently through reused owning validation rules, without calling final report mutators. Missing/malformed metadata or stage, malformed source identity or incompatible run binding: throw safe INVALID_CONTEXT, no context/guessed identity. publishPartialReport catches INVALID_CONTEXT and returns {status:'failed',generationKey:null,currentPath:null,reason:'INVALID_CONTEXT'}; readPartialReport returns {status:'invalid',generationKey:null,expectedGenerationKey:null,path:null}. No artifact publication from unidentified data. Context renderer accepts only its defined detached data shape; malformed context throws INVALID_CONTEXT before reading getters/custom objects. Pure rendering never consults filesystem/current global state.

Fixed input bounds before parsing: run-metadata/stage-state <=1MiB each; coverage-ledger/findings <=5MiB each (retain upstream's stricter rules if applicable); candidates/decisions/critic <=16MiB each; any absent optional artifact explicit absent; unreadable/oversized optional artifact is rejected with a safe blocker and no data-derived counts. A context-invalid required identity/stage file fails as above. Bind exact bytes for within-bound present files; oversized files bind {state:'oversized',observedBytes} plus a streaming SHA256 if safely readable (do not allocate the whole file). Any inability to obtain a stable binding makes freshness invalid, never current. Journal's own validated1GiB/10000row bounds remain owning; do not make a1MiB report input barrier for that journal.

Prior-runs.json, events.jsonl, architecture.md and raw prompt files are NOT consulted by this partial renderer. No unbound prior/history/body content appears. Reused final renderer helpers must receive the partial context only and cannot implicitly call reportContext/readPool on extra paths. If future requirements add such content, extend the fixed binding list and freeze an acceptance case first. Current fixed list is sufficient for stage/profile, valid candidate/decision/needs_validation and coverage presentation.

Known decision records: derive pending/needs_validation/rejected only from the current owning candidate/decision/findings parsers and semantic validation. A malformed decisions.json contributes no decisions, adds ARTIFACT_REJECTED with artifact decisions.json, and never silently marks candidate resolved. Valid candidate identities remain pending when decision authority is rejected. A valid needs_validation record displays exact blocker and retains that disposition. Rejected is not a vulnerability; it stays distinctly labeled. Every rendered value is either bound artifact data, owning validated journal data or fixed renderer text. No body/source hashing as semantic finding validation.


Freshness gate clarification: after EVERY publication attempt, the eventual native host must call readPartialReport and require status==='current' before admitting a new dispatch. published/replayed alone is insufficient: an unavailable-journal generation is useful historical prose but read status invalid, therefore report_stale control remains/set, already-inflight callbacks drain and new dispatch is blocked. Missing,invalid,stale or failed all prevent release of that gate. No prior report_stale flag is required to trigger this rule.

# SA-01b: static root-path symlink refusal

External correction draft; no execution before independent review/root authorization. Follows SA-01 before journal integration. Original SA-01 six frozen cases unchanged. No contract narrowing, race, capture, signals, target execution or containment claim.

Owning module remains snapshot-protection.mjs, same inspectSnapshotProtection(tree) API and diagnostic vocabulary. Absolute input containing any explicit . or .. component is rejected as `{ok:false,problems:[{path:'.',code:'INVALID_ROOT'}]}` before filesystem traversal; this precedence applies even if a component also names a symlink. Do not normalize away the forbidden components. Existing trailing path separators remain accepted for an otherwise canonical real root. Relative/nonstring remains INVALID_ROOT.

For an otherwise accepted absolute path, inspect its existing ancestor components with lstat, without resolving through symlinks. Any root or ancestor symlink produces exactly root-relative SYMLINK, before enumerating the addressed subtree. Missing/unreadable ancestor remains IO_ERROR with root-relative diagnostics; no absolute paths/raw errors. A symlink must not be followed merely because the final component is a directory. Scope is static paths, not protection against concurrent replacement. Init's host-created canonical tree already had correct ordering; this closes exported inspector's broader absolute-path contract.

Three ordinary fixtures: (1) owned static directory symlink ancestor to an inert sealed child yields root SYMLINK; (2) root symlink followed by /. plus explicit dot/dotdot variants yields INVALID_ROOT, not normalized traversal; (3) canonical real sealed tree, including trailing separator spelling, returns expected successful permission result with unchanged bytes/modes. All fixtures live under mkdtemp, contain only fixed inert data, and restore directory write modes only for cleanup. No denied-write attempts or source code invocation. Tests dynamically import intended module before fixture setup. Do not call initial-red or corrected-positive tests until authorized. Permission-bit success still does not prove same-user containment/ACL/read-only mount/tool isolation.
